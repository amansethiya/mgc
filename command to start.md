## 1. Install prerequisites (first time only)

Check your existing installations:

```powershell
node --version
npm --version
py --list
py -3.11 --version
```

If Node.js 22 or Python 3.11 is missing, install the appropriate package using Windows Package Manager (skip packages already installed):

```powershell
winget install --id OpenJS.NodeJS.22 --exact
winget install --id Python.Python.3.11 --exact
```

If a package is unavailable through winget, use the official [Node.js downloads](https://nodejs.org/en/download) or [Python downloads](https://www.python.org/downloads/windows/). Restart VS Code after installation and repeat the version checks. Multiple Python versions can coexist.

MongoDB is also required: use an existing MongoDB Atlas cluster or install [MongoDB Community Server](https://www.mongodb.com/try/download/community) locally. No GitHub account, Docker or Git commands are required to run the extracted project.

## 2. Open the project (first time only)

Open the extracted `music-genre-classifier` folder in VS Code. The root contains `package.json`, `frontend/`, `backend/`, `ml-service/` and `scripts/`.

Example for a Windows installation; change the path if needed:

```powershell
cd "$HOME\OneDrive\Desktop\music-genre-classifier"
code .
```

If `code` is not recognized, open the folder using VS Code's File > Open Folder menu.

## 3. Install JavaScript dependencies (first time only)

From the project root:

```powershell
npm run setup
npm run install:js
```

`setup` creates `backend/.env` with a randomly generated JWT secret and preserves an existing file. `install:js` installs dependencies for both applications.

Equivalent manual dependency installation (only needed if troubleshooting):

```powershell
npm --prefix backend install
npm --prefix frontend install
```

## 4. Configure and start MongoDB

From the project root, open the environment file:

```powershell
code backend/.env
```

Or open it directly in the VS Code Explorer. The generated file contains these settings:

```dotenv
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017/music_genre_classifier
JWT_SECRET=<keep the actual random secret generated by npm run setup>
ML_URL=http://127.0.0.1:8000
APP_ORIGIN=http://localhost:5173
NODE_ENV=development
```

The JWT line above is illustrative; do not replace the generated secret with that placeholder.

### Option A — Local MongoDB

If MongoDB Community Server was installed as a Windows service named `MongoDB`, check it:

```powershell
Get-Service -Name MongoDB
```

If it is stopped, run the following in an Administrator PowerShell terminal:

```powershell
Start-Service -Name MongoDB
```

Check the local port:

```powershell
Test-NetConnection 127.0.0.1 -Port 27017
```

Keep the default `MONGODB_URI`. If the service is not found, install MongoDB or use Atlas instead; the service name can vary by installation.

### Option B — MongoDB Atlas

1. Open [MongoDB Atlas](https://www.mongodb.com/atlas), create or select a cluster, and create a database user with read/write access to the project database.
2. Allow your current public IP address in Network Access.
3. Copy the driver's connection string and set `MONGODB_URI` in `backend/.env` to your actual URI, including the database name `music_genre_classifier`.

Example only:

```dotenv
MONGODB_URI=mongodb+srv://USERNAME:PASSWORD@CLUSTER_HOST/music_genre_classifier?retryWrites=true&w=majority
```

Replace the placeholders, URL-encode special characters in the credentials, and save the file. Never commit `.env` or database credentials. Atlas does not require running a local MongoDB service.

## 5. Set up the Python ML environment (first time only)

From the project root:

```powershell
cd ml-service
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements.txt
python -m pip check
```

Confirm Python reports `3.11.x` before installing dependencies. Do not use Python 3.15 for this project's current dependency ranges.

If PowerShell blocks activation, you can install and run everything without activation using the environment's executable directly:

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Alternatively, allow scripts for the current PowerShell session only and retry activation:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### Repair an environment created with the wrong Python version

Run only if the existing `.venv` uses an incompatible Python version. Stop any services using it first. From `ml-service`, deactivate it if active:

```powershell
deactivate
```

Then, from the same directory:

```powershell
py -3.11 --version
Remove-Item -Recurse -Force .venv
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

This removes only the old virtual environment, not your source code, dataset or trained model. A `pandas` metadata error involving `vswhere.exe` followed by `No module named uvicorn` can result from an incompatible Python version and an aborted dependency installation. Verify that the new environment uses 3.11 rather than installing C++ build tools as a first fix.

## 6. Train the actual machine learning model (first time or retraining)

Download the [GTZAN dataset](https://www.kaggle.com/datasets/andradaolteanu/gtzan-dataset-music-genre-recognition). Extract its `genres_original` folder into `ml-service/dataset/`. Do not add an extra nested `Data` folder between these directories.

Expected path:

```text
ml-service/dataset/genres_original/
  blues/
  classical/
  country/
  disco/
  hiphop/
  jazz/
  metal/
  pop/
  reggae/
  rock/
```

From `ml-service`:

```powershell
Get-ChildItem .\dataset\genres_original -Directory
.\.venv\Scripts\python.exe train.py --dataset dataset/genres_original
```

For a reviewed group/exclusion manifest (optional; prepare the CSV first):

```powershell
.\.venv\Scripts\python.exe train.py --dataset dataset/genres_original --manifest dataset/groups.csv
```

Training compares Random Forest and SVM and exports the selected model. Verify outputs:

```powershell
Get-ChildItem .\models
Get-ChildItem .\evaluation
Get-Content .\evaluation\metrics.json
```

The required model is `models/genre_model.joblib`. Evaluation files are generated from actual experiments. The default split is track-disjoint, not guaranteed artist-disjoint; see `docs/ml-method.md` for manifest details and limitations.

If your teammate has already trained the model, copy the trusted artifact to `ml-service/models/genre_model.joblib` and use matching dependency versions instead of retraining. Do not load untrusted Joblib artifacts.

Optional: export the training environment's package versions from `ml-service` for your teammate:

```powershell
.\.venv\Scripts\python.exe -m pip freeze > requirements-lock.txt
```

On the receiving computer, install the shared lock file into its Python 3.11 environment (on a compatible platform):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

**Training is not required just to start the web application.** Without a trained model, classification is unavailable and the prediction service returns HTTP 503. The application does not generate fake predictions. Restart FastAPI after training or replacing the artifact.

## 7. Start the complete project (every session)

Make sure MongoDB is running locally or Atlas is reachable. Open **three separate VS Code terminals**, each initially at the project root. Keep all three running.

### Terminal 1 — Python FastAPI (port 8000)

```powershell
cd ml-service
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Or, if the Python virtual environment is activated:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Check [FastAPI Swagger](http://127.0.0.1:8000/docs) and [ML health](http://127.0.0.1:8000/health).

### Terminal 2 — Node.js backend (port 5000)

From the project root:

```powershell
npm run dev:backend
```

Expected server log: `API listening at http://127.0.0.1:5000`.

Check [backend health](http://127.0.0.1:5000/api/v1/health).

### Terminal 3 — React frontend (port 5173)

From the project root:

```powershell
npm run dev:frontend
```

Open **[http://localhost:5173](http://localhost:5173)**. Use `localhost` exactly as configured in `APP_ORIGIN`; do not switch the frontend hostname to `127.0.0.1` without updating the configuration.

| Backend   | Project root           | http://127.0.0.1:5000/api/v1/health |

## 8. Verify the running services

Open a fourth PowerShell terminal:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:5000/api/v1/health | ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:5000/api/v1/model/info | ConvertTo-Json -Depth 5
```

The ML health response should contain `data.status: ok` and `data.modelReady: true` after training. The backend health response should contain `data.database: connected`. Before training, `modelReady: false` is expected.

In the browser, register an account, log in, upload an MP3 or WAV (at least 5 seconds, no larger than 25 MB), check the genre and probabilities, and verify history and dashboard updates.

## 10. Stop or restart the project

Press `Ctrl+C` in each running service terminal. If you activated the virtual environment, you can then run `deactivate` in the Python terminal. To start again, repeat Section 7; no reinstall or retraining is required unless dependencies or the model change. If `.env` changes, restart Node.js. If the model changes, restart FastAPI.

## 11. Troubleshooting commands (Windows)

| Problem                            | Command or action                                                                 |
| ---------------------------------- | --------------------------------------------------------------------------------- |
| `No module named uvicorn`          | Check `.venv` Python version and reinstall requirements successfully (Section 5). |
| Python 3.15 / Pandas build failure | Recreate `.venv` using Python 3.11 (Section 5).                                   |
| PowerShell activation blocked      | Use `.\.venv\Scripts\python.exe` directly (Section 5).                            |
| `npm.ps1` blocked                  | Use `npm.cmd` instead of `npm`, or use Command Prompt.                            |
| MongoDB connection refused         | Check service, URI, port or Atlas network access.                                 |
| Atlas DNS/SRV error                | Check your internet/DNS and the copied cluster hostname.                          |
| Invalid JWT secret                 | Keep the generated secret; it must be at least 32 characters.                     |
| Model not ready                    | Train or copy the model and restart FastAPI.                                      |
| Unsupported MP3 decoding           | Try WAV; if FFmpeg is installed, convert using `ffmpeg -i input.mp3 output.wav`.  |

To identify processes listening on project ports:

```powershell
Get-NetTCPConnection -LocalPort 5173,5000,8000,27017 -State Listen -ErrorAction SilentlyContinue | Select-Object LocalPort,OwningProcess
```

Inspect an identified process (replace the example ID):

```powershell
Get-Process -Id 1234
```

Stop it only if it is your own stale project process, preferably with `Ctrl+C` in the original terminal. Do not terminate unknown system processes.

## Git & GitHub Setup

Git and GitHub are used for version control, source code
management and collaboration between team members.

### 1. Verify Git Installation

```bash
git --version
```

If Git is not installed, download it from:
https://git-scm.com/downloads

### 2. Configure Git

Run these commands once on your computer:

```bash
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```

Verify the configuration:

```bash
git config --global --list
```

### 3. Initialize the Repository

Open the terminal inside the project root directory.

```bash
git init
git status
```

### 4. Stage and Commit Project Files

Before staging, ensure `.gitignore` excludes:

- node_modules/
- .venv/
- .env
- **pycache**/
- Uploaded audio files
- GTZAN dataset
- Trained model binaries

Stage the project files:

```bash
git add .
git status
```

Create the initial commit:

```bash
git commit -m "Initial commit: GenreLab Music Genre Classifier"
```

### 5. Create a GitHub Repository

1. Visit https://github.com/new

3. Select Public or Private.

### 16. Troubleshooting

#### Remote origin already exists

```bash
git remote set-url origin https://github.com/amansethiya/mgc.git
```

#### Remove accidentally tracked environment files

```bash
git rm --cached backend/.env
git commit -m "fix: remove environment file from tracking"
git push
```

If credentials were already pushed to GitHub, rotate them
immediately. Removing a file does not remove it from
previous commits.

#### Remove accidentally tracked node_modules

```bash
git rm -r --cached --ignore-unmatch node_modules frontend/node_modules backend/node_modules
git commit -m "fix: remove dependencies from Git tracking"
git push
```

#### Check remote repository connection

```bash
git remote -v
git ls-remote origin
```

### 17. Security Guidelines

- Never commit database credentials.
- Never commit JWT secrets or API keys.
- Never upload .env files.
- Use .env.example for configuration templates.
- Exclude datasets and large model binaries.
- Exclude Python virtual environments.
- Exclude node_modules directories.
- Review staged files before committing.
- Avoid force-pushing shared branches.
- Use Pull Requests for major changes.

The integration test requires the trained model, all services running and a disposable database, as noted above.
